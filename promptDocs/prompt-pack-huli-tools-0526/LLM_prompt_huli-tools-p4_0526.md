# LLM Prompt huli-tools Phase 4/5

## 阶段目标

完成用户可见的小程序公共体验：总入口应用列表、我的账户、积分余额、充值包、订单、积分流水、使用记录和示例工具页面。Phase 4 完成后，普通用户应能在小程序里完成“进入首页 -> 进入示例工具 -> 扣费执行 -> 我的页查看余额/流水 -> 充值并到账”的端到端演示。

- 可参考测试文档：`/Users/huli-dev/Documents/huli-tools/promptDocs/prompt-pack-huli-tools-0526/test_case_huli-tools_0526.md`
- 已完成前序阶段：Phase 1-3 的公共云函数、seed、积分和支付订单接口。

## 任务清单

1. 前端服务层：
   - 新增 `miniprogram/services/` 或 `miniprogram/utils/` 中的云函数调用封装。
   - 统一处理 `{ ok, data, error }` 响应、加载态、toast 错误。
   - 前端不得直接写公共 collection。
2. 首页总入口：
   - 调用 `coreUser.bootstrap` 初始化用户。
   - 调用 `coreApp.listApps` 展示应用列表。
   - `active` 应用可进入；`coming_soon` 显示但不可进入；`disabled` 不展示。
3. 我的页：
   - 展示用户摘要、可用积分、冻结积分。
   - 提供进入充值、订单、积分流水、使用记录的入口。
4. 充值与订单：
   - 新增充值页，展示固定充值包，支持创建订单。
   - 在 mock 支付可用时提供“模拟支付”按钮，并标识为开发/测试能力。
   - 新增订单列表页，展示订单号、套餐、金额、状态和时间。
5. 积分流水与使用记录：
   - 新增积分流水页，分页或简单列表展示充值、冻结、结算、释放、调整。
   - 新增使用记录页，展示应用、状态、消耗积分、时间、错误摘要。
6. 示例工具页：
   - 路由建议使用 Phase 1 seed 的 `/pages/tools/demo-sum/index`。
   - 展示本次消耗积分，输入两个数字，执行时创建 usage 并调用示例工具。
   - 成功后刷新余额；失败时展示明确错误并确保冻结积分释放。
7. UI 质量：
   - 保持克制、工具型设计，不做营销 landing page。
   - 移动端文本不能溢出按钮/卡片。
   - 保持现有 tabbar，“首页”“我的”仍是主入口。

## 范围边界

要做：

- 公共底座的完整用户可见闭环和必要页面。

不要做：

- 不做管理员管理页，Phase 5 只要求云函数管理接口和审计。
- 不做复杂品牌视觉、动画或无关业务工具。
- 不为了 UI 引入大型组件库。

## 实现约束

- 更新 `miniprogram/app.json` 页面列表，确保新页面可在微信开发者工具编译。
- 所有页面都要处理空状态、加载状态、错误状态。
- 页面 JS 可用 `node --check` 通过语法检查。
- 路由和 `apps.entryPage` 必须一致；如果调整示例工具路由，也要同步 seed 数据和文档。
- 所有金额展示从分转换为元，所有积分展示为整数。

## 验证要求

至少运行：

```bash
bash scripts/check-js.sh
git diff --check
```

微信开发者工具人工验证：

- 打开小程序，首页能展示 seed 应用列表。

- 执行示例工具成功后，“我的”页余额减少，流水和使用记录增加。
- 充值页能创建订单并 mock 支付到账。
- 订单页、流水页、使用记录页在空数据和有数据时都能正常展示。
