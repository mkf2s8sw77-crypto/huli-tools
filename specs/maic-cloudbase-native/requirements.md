# MAIC CloudBase 原生化 — 需求

## 问题与范围

MAIC 课程生成仍依赖本机 Next.js/Worker、PM2 和 `/maic/` 反向代理，其他开发环境只能看到 `maic` 应用入口而无法获得完整运行时。本次将生成链路迁入 `huli-tools` 的 CloudBase Event Functions，保留现有小程序播放器、课程、进度和公共 usage 契约，并永久下线独立 MAIC Web 服务。

## 用户故事

1. 作为学习者，我希望提交课程主题后即使退出小程序，课程仍能在后台生成并正确结算。
2. 作为学习者，我希望失败、取消或超时不会留下冻结积分或不可恢复任务。
3. 作为运营者，我希望迁移期间能停用 MAIC，验收通过后以 0 积分恢复启用，其他工具不受影响。
4. 作为维护者，我希望任意开发环境只需拉取 `huli-tools/main` 即可维护 MAIC，不依赖本机 Web、SQLite、PM2 或 HMAC 服务。
5. 作为维护者，我希望可选择性跟踪 OpenMAIC 的协议和生成质量更新，而不会自动引入 Web/编辑器/导出模块。

## 验收标准

1. 当用户创建课程任务时，系统应写入 `queued` 任务并返回兼容响应；新任务 `jobId` 为空且标记废弃。
2. 当每分钟 Worker 被触发时，系统应通过数据库租约保证全局最多一个生成任务处于执行窗口。
3. 当模型返回合法课程时，系统应依次进入 `processing`、`importing`、`succeeded`，导入课程后正确结束 usage 并清理 artifact。
4. 当模型首次返回协议错误时，系统应最多进行一次纠错重试；仍错误时应生成确定性的精简兜底课程。
5. 当模型出现网络或限流错误时，系统应最多重试三次；耗尽后应标记失败并结束 usage。
6. 当任务超过 45 分钟、被显式取消或租约失效时，reconcile 应恢复或终结任务，不得执行模型生成。
7. 当同一用户当天已创建三门课程时，系统应拒绝第四次创建且不得创建 usage。
8. 当课程内容包含 HTML、脚本、危险 URL、无效 PBL 引用或 `navigate` 时，系统应拒绝或规范化为安全的原生协议。
9. 当既有课程含 assets 或旧协议动作时，小程序应继续播放和删除；新课程首版 assets 应为空。
10. 当迁移完成时，本机 MAIC 目录、PM2 进程、3000/60322 监听和 `/maic/` 路由应全部不存在，远端 `huli-MAIC` 仅保留归档。
11. 当上线验收通过时，`maic` 应恢复 `active` 且 `costPoints=0`；失败时应保持 `disabled`，不得恢复独立服务。

## 约束与非目标

- 仅使用小程序原生页面、CloudBase 云函数/数据库和 MiniMax，不新增独立后端。
- 不迁移 Next.js、SQLite、Drizzle、编辑器、导出、图片、语音、视频或 WebView。
- 不删除既有课程、学习进度和资产。
- 不自动提交微信审核或发布正式版。
