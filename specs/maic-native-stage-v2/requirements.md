# MAIC 原生课堂舞台 V2 — 需求

## 问题与范围

当前 MAIC 小程序播放器会执行模型生成的 `navigate` 动作，导致场景在用户未操作时自动跳转；同时所有场景都被压平为纵向白卡，缺失 MAIC 的舞台、教师、动作编排和互动停顿感。

本次覆盖 MAIC 集成生成器与 huli-tools 原生播放器，不引入 WebView，不同步 MAIC Web 课程库，不改变现有 CloudBase 课程归属与 usage 链路。

## 用户故事

1. 作为学习者，我希望课程只在我明确操作后翻页，避免错过讲解或互动。
2. 作为学习者，我希望感受到教师正在围绕舞台内容讲解，而不是阅读普通图文文章。
3. 作为学习者，我希望测验、互动和 PBL 必须等待我完成操作。
4. 作为维护者，我希望旧 `maic-miniapp/1` 课程仍可播放，新课程不再生成危险的自动翻页动作。

## 验收标准

1. 当播放器读取到旧课程中的 `navigate` 动作时，系统应忽略该动作，不得改变当前场景。
2. 当用户切换场景、页面隐藏或退出播放器时，系统应取消当前动作序列，旧动作不得继续影响页面。
3. 当播放 `speech` 动作时，系统应按文本长度给出可读停留时间，并在舞台教师旁白区域呈现讲解状态。
4. 当场景为 `quiz`、`interaction` 或 `pbl` 时，系统应等待用户完成必要操作，不得自动进入下一场景。
5. 当场景为 `slide` 时，系统应使用原生舞台布局呈现标题、内容与动作聚焦，而不是单一居中长卡。
6. 当课程缺少新版展示元数据时，系统应根据现有场景内容推导稳定布局，保证旧课程兼容。
7. 当新课程由 MAIC 集成生成器创建时，生成结果不得包含 `navigate` 动作，并应为场景提供可选的原生展示提示。
8. 当执行项目质量门禁时，MAIC 协议测试、huli-tools JavaScript/边界检查和小程序预览应通过。

## 非目标

- 不把 React、HTML、CSS 或 MAIC Web 运行时搬入小程序。
- 不在本次实现实时 Agent 对话、Web 白板或任意脚本互动。
- 不修改生产环境 `sys.huli.sh.cn`。
